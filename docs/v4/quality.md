# Критерии качества

Этот документ задаёт обязательные проверки качества монорепозитория и границы их
покрытия. Контракт — единственный, версии 4; текущая спецификация —
[README.md](README.md).

## Автоматические проверки

| Критерий | Проверка и граница гарантии |
| --- | --- |
| Сборка, lint, типы и форматирование workspace | CI: `pnpm build`, `pnpm lint`, `pnpm typecheck`, `pnpm format:check`. Форматирование исключает временные артефакты и сгенерированные token modules: последние проверяются по источнику. |
| Node-тесты maintainer scripts, core, system и tools | `pnpm test` запускает поддерживаемые Node suites для scripts, core, систем и tools после сборки. Они проверяют утилиты, контракты и сценарии этих пакетов; сами по себе не подтверждают поведение каждого компонента в браузере. |
| Согласованность версий | `pnpm ds:sync-versions --check` подтверждает равенство версий package, runtime, манифестов и реестра без записи. |
| Активная документация | `pnpm ds:check-docs` проверяет структуру, локальные ссылки и соответствие документации контрактам. Это не проверка качества каждого примера визуально. |
| Пакеты | `pnpm ds:check <id>` валидирует пакет: обязательные компоненты, заявленные дополнительные, runtime-карту, публичные экспорты, манифест (`schemaVersion: 4`, `contractVersion: 4`), токены, CSS и Tailwind-мост. |
| Инструменты и lifecycle | `pnpm ds:check-tools` собирает и упаковывает core, системы A/B, свежий пакет из шаблона и `@prism-system/tools`, проверяет публичные экспорты, манифесты, CSS и token exports, выполняет typecheck и runtime resolution импортов из изолированного consumer, проверяет обычный CSS и компилирует Tailwind v4 на точной версии для A/B. |
| Полный приёмочный прогон | `pnpm ds:check-all` — единый gate поверх собранных и упакованных артефактов; включает проверки инструментов и документации, поэтому отдельно учитывать `ds:check-tools`/`ds:check-docs` в нём не нужно. Он также сверяет снимок отслеживаемых версий, конфигураций и манифестов до и после, проверяет, что lockfiles репозитория не меняются, и выполняет release-проверки на временных копиях. `ds:release` должен блокировать неполный или несогласованный пакет; harness проверяет fail-closed поведение и отсутствие изменений, упаковки и публикации при dry-run/ошибках. |

Общий verification workflow только проверяет код и артефакты. Изменение версий
проходит через Changesets и `pnpm version-packages-and-sync` в version PR.
Публикация выполняется отдельным [publish.yml](../../.github/workflows/publish.yml)
после merge version PR через environment `npm-release`; решение о выпуске
остаётся отдельным этапом review.

## Локальный запуск и CI

CI, release и проверка перед publish используют один workflow:
[verify.yml](../../.github/workflows/verify.yml).
Он устанавливает зависимости с frozen lockfile и выполняет все проверки из таблицы.
Ошибки блокируют продолжение workflow; нет `continue-on-error` или автоматического
повтора тестов. Браузер не устанавливается и не запускается в CI.

Для воспроизведения после `pnpm install --frozen-lockfile`:

```bash
pnpm format:check
pnpm build
pnpm lint
pnpm typecheck
pnpm test
pnpm ds:sync-versions --check
pnpm ds:check-docs
pnpm ds:check-all
```

`ds:check-tools` и `ds:check-all` используют сеть для временной установки точных версий
Tailwind в каталог своего запуска. Недоступность registry проваливает
соответствующий шаг, а не считается успешной проверкой.

## Ручной review изменений интерфейса

Для изменённых компонентов и Showcase reviewer проверяет применимые пункты на живом сценарии обеих систем:

- управление клавиатурой, видимый и логичный focus;
- доступные имена и связи `label`, `aria-describedby`, ошибки и подсказки;
- состояния loading, empty, error и success там, где компонент или сценарий их поддерживает;
- компоновку на узком и широком экране;
- поведение при reduced motion и достаточную различимость контраста.

CI не доказывает браузерное поведение, соответствие WCAG или визуальную идентичность. Эти пункты требуют ручного review. Peer ranges в package metadata не доказывают совместимость каждой комбинации React 18/19 и зависимостей; новые или рискованные комбинации требуют отдельной проверки.

## Постоянные гарантии

- Текущий контракт — один, версии 4: ровно 29 обязательных компонентов и только
  реализованные дополнительные компоненты, объявленные системой; пустые заглушки
  недопустимы.
- Форма сгенерированного манифеста одна: `schemaVersion: 4` при package-owned
  descriptor `schemaVersion: 3`. `capabilities.categories` — канонический перечень
  категорий, а не список доступности; поддержка по-прежнему определяется ключами
  `components`. Читатели schema 3 обновляются вместе с системой: старый `prism-ds`
  не читает schema 4, а текущий инструмент не принимает schema 3.
- Пакет системы владеет токенами и визуальным оформлением. `tokens.source.json` —
  источник визуальных значений; `ui-core` остаётся неоформленной общей основой,
  приложения отвечают за композицию.
- Изменение несовместимого публичного API требует Changeset и документации миграции.
  Автоматические проверки помогают обнаружить рассогласование, а совместимость и
  понятность миграции оценивает review.
- Подготовка релиза проверяет и упаковывает артефакт, но не публикует его. Решение о
  публикации принимается отдельно.
