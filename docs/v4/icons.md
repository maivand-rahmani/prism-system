# Каталог иконок Prism

Иконки — отдельный необязательный словарь из 50 смысловых имён. Он не является частью
контракта компонентов версии 4, не входит в `REQUIRED_COMPONENTS`/`OPTIONAL_COMPONENTS`,
не создаёт capability-категорию и не требует второго runtime-реестра дизайн-систем.

## Что кому принадлежит

| Слой | Владеет |
| --- | --- |
| `@prism-system/ui-core` | Канонические имена, группы, `IconName`, `IconProps`, `IconComponent`, соглашение `${Name}Icon`, проверки имени. Никаких SVG, Lucide, цветов, толщины штриха, размера по умолчанию и анимации. |
| Дизайн-система | Реальный глиф, толщина штриха, размер по умолчанию, наследование цвета, необязательное движение, CSS и правило замены. |
| `design-system.source.json` | Явная декларация: непустое подмножество канонических имён в каноническом порядке и зарезервированный вход `./icons`. |
| `design-system.json` | Сгенерированная доступность: `publicApi["./icons"]` и `entrypoints["./icons"].requirements`. Отдельного поля `icons` в манифесте нет. |
| `prism-ds` | Офлайн-каталог, публичный импорт, проверка использования, сравнение при `switch`, диагностика. |
| Showcase | Композиция каталога: сетка, поиск, пустое состояние. Внешний вид иконок не переопределяет. |

## 50 канонических имён

Порядок ниже — канонический; `ICON_NAMES` в core и манифест используют его для
декларации, а `publicApi` может быть отсортирован иначе.

### Навигация (10)

`ArrowLeft`, `ArrowRight`, `ArrowUp`, `ArrowDown`, `ChevronLeft`, `ChevronRight`,
`ChevronUp`, `ChevronDown`, `Menu`, `Home`.

### Действия (10)

`Plus`, `Minus`, `Close`, `Check`, `Search`, `Filter`, `Settings`, `Edit`, `Trash`,
`Copy`.

### Файлы и обмен (10)

`Download`, `Upload`, `Share`, `Link`, `ExternalLink`, `File`, `Folder`, `Image`,
`Calendar`, `Clock`.

### Состояния и обратная связь (10)

`Info`, `Help`, `Warning`, `Error`, `Success`, `Loading`, `Eye`, `EyeOff`, `Lock`,
`Unlock`.

### Пользователь и интерфейс (10)

`User`, `Users`, `Mail`, `Bell`, `Heart`, `Star`, `MoreHorizontal`, `MoreVertical`,
`Refresh`, `LogOut`.

## Публичный API

Одна иконка — один стабильный именованный экспорт из выделенного входа:

```tsx
import { SearchIcon } from "@prism-system/ui-system-plr/icons";

<SearchIcon aria-hidden="true" />
```

- Имя Prism смысловое и стабильное; Lucide-глиф — деталь реализации. `Close` может
  рисоваться Lucide `X`, но публичное имя остаётся `Close`.
- Экспорт всегда `${Name}Icon`; имена Lucide не являются публичным API Prism.
- `./icons` — отдельный ESM/CJS-вход с именованными экспортами и tree-shaking.
  Импорт одной иконки не требует полного набора.
- `IconProps` из core: `size?: number | string`, `label?: string`,
  `decorative?: boolean`, стандартные SVG-props, `className`, `style`.
- `ref` forwarded на `SVGSVGElement`; реализации используют `forwardRef`, поэтому
  поведение одинаково на React 18 и 19.
- Цвет наследуется через `currentColor`; система задаёт толщину штриха и размер по
  умолчанию (`1em` — конвенция Prism), но потребитель может переопределить `size` и
  `strokeWidth` в конкретной композиции.
- После замены Lucide на собственный SVG меняется только файл глифа; публичный импорт,
  props и `IconComponent` не меняются.

## Доступность

| Ситуация | Правило |
| --- | --- |
| Декоративная иконка рядом с текстом | Значения по умолчанию достаточно: SVG получает `aria-hidden="true"` и не попадает в фокус. |
| Смысловая иконка без текста | Передайте `label="…"` или `aria-label`/`aria-labelledby`; SVG получает `role="img"`. |
| Кнопка только с иконкой | Имя задаёт сама кнопка (`aria-label` или видимый текст); иконка внутри остаётся декоративной. |
| Состояние | Не передавайте состояние только цветом; используйте текст, форму, `aria-*` или подпись. |
| Клавиатура | Иконка не создаёт остановку фокуса и не перехватывает клавиши. |
| Движение | `LoadingIcon` статичен по умолчанию; необязательный spin-класс удаляется при `prefers-reduced-motion`. |

Не используйте `title`-атрибут как единственное доступное имя: он не заменяет
`aria-label` и не гарантирует объявление скринридером.

## Декларация и манифест

`design-system.source.json`:

```json
{
  "entrypoints": {
    "./icons": {
      "source": "./src/icons/index.ts",
      "requires": ["lucide-react"]
    }
  },
  "icons": {
    "entrypoint": "./icons",
    "names": ["ArrowLeft", "ArrowRight"]
  }
}
```

Правила проверки:

- `icons` необязателен; отсутствие означает «иконок нет». Пустая секция запрещена.
- `entrypoint` всегда `./icons`; он должен быть объявлен в `entrypoints`.
- `names` — непустое уникальное подмножество 50 канонических имён в каноническом
  порядке. Неизвестное имя, дубль или нарушение порядка отклоняются.
- Реальные runtime-экспорты `./icons` должны быть ровно набором `${name}Icon` для
  объявленных имён. Лишний, отсутствующий или неканонический экспорт — ошибка.
- Канонические `${Name}Icon`-экспорты не могут публиковаться из других входов.
- Вход `./icons` без секции `icons` зарезервирован и отклоняется.

Сгенерированный `design-system.json` остаётся `schemaVersion: 5`:

```json
{
  "entrypoints": {
    "./icons": {
      "requirements": [
        { "name": "lucide-react", "kind": "dependency", "range": "1.70.0", "optional": false }
      ]
    }
  },
  "publicApi": {
    "./icons": ["ArrowLeftIcon", "ArrowRightIcon"]
  }
}
```

Почему без нового поля и без повышения схемы:

- `entrypoints`/`publicApi` уже описывают реальный опубликованный код, поэтому
  доступность иконки — это фактический экспорт, а не второй список.
- Выпущенный `prism-ds` со схемой 5 продолжает читать манифест: он видит обычный
  дополнительный code-вход и не показывает каталог иконок, пока CLI не обновлён.
- Обновлённый `prism-ds` читает `publicApi["./icons"]` как каталог. Отсутствие входа —
  корректное «иконок нет», а не ошибка.
- `contractVersion` остаётся 4: контракт компонентов не менялся.

## Инструменты

```bash
prism-ds icons --cwd <consumer-root> [--json]
prism-ds icons Search --cwd <consumer-root> [--json]
```

- Каталог офлайн, read-only, только по `./manifest`; код пакета не исполняется.
- `--json` стабилен: `supported`, `entrypoint`, `importPath`, `counts`, `icons`,
  `available`, `unavailable`, `categories`, `requested`.
- Система без входа `./icons`: `supported: false`, 0 доступных, 50 известных-но-недоступных,
  код выхода 0. Неизвестное имя — ошибка; известное, но не объявленное — `available: false`.
- Showcase: `/showcase/<id>/icons` и вкладка Icons; пустое состояние для системы без
  иконок.
- `check-usage` проверяет именованные/namespace-импорты из `./icons`; динамические,
  computed и `export *` помечаются как непроверенные, а не как успешные.
- `switch` блокирует отсутствующие у целевой системы иконки, учитывает смену входа и
  автоматически выбирает `./icons` для проверки его requirements.
- `check`/`doctor` не считают отсутствие иконок поломкой; объявленный, но сломанный
  каталог — считают.

## Создание и замена

Новая система из `templates/design-system` уже содержит:

```text
src/icons/
├── index.ts          # 50 экспортов
├── icon-base.tsx     # общий IconProps, aria, currentColor, strokeWidth
├── icons.css         # выравнивание и opt-in spin
└── <Name>.tsx        # по одному глифу на файл
```

Замена одной иконки:

1. Оставьте имя файла, публичный экспорт и `IconProps` без изменений.
2. Замените glyph на собственный SVG-компонент с теми же SVG-props.
3. Обновите при необходимости документацию/пример, но не манифест вручную.
4. Запустите `pnpm ds:manifest <id> --write` и `pnpm ds:check <id>`.

Удаление иконки:

1. Удалите имя из `icons.names`.
2. Удалите реальный экспорт из `src/icons`.
3. Перегенерируйте манифест и проверьте потребителей: `prism-ds check-usage` и
   `prism-ds switch ... --dry-run` покажут оставшиеся импорты.

## Визуальные правила

Это рекомендации, а не требование одинаковости систем:

- сетка 24×24, ключевые формы выровнены по целым пикселям; оптический размер важнее
  геометрического;
- толщина штриха согласована с типографикой и контролами; PLR использует `1.75`,
  шаблон — `1.75` как спокойный современный дефолт;
- скруглённые окончания и соединения, если это язык системы; не смешивайте стили в
  одном наборе;
- цвет — `currentColor`; не зашивайте палитру в SVG и не переносите палитру системы в
  core;
- проверяйте пары `Check`/`Success`, `Close`/`Error`, `Warning`/`Error`: они должны
  различаться формой, а не только цветом;
- проверяйте иконку в тексте, в кнопке, в поле и в тёмной теме; `1em` следует за
  контекстом, `size` задавайте только при необходимости;
- не анимируйте по умолчанию; если движение есть, учитывайте
  `prefers-reduced-motion`.

## Лицензия

Базовая реализация PLR и шаблона использует [`lucide-react`](https://lucide.dev)
(ISC) как runtime-зависимость. SVG-пути не копируются и не распространяются пакетом,
поэтому лицензия Lucide применяется к установленной зависимости. Собственные рисунки,
CSS, толщина штриха и движение принадлежат соответствующей дизайн-системе под её
лицензией. При копировании SVG-исходников сохраните уведомление Lucide и укажите
происхождение.
